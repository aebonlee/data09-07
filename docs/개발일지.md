## 결정과 이유

- **화면은 수강생 UI 시안을 따랐습니다.** 좌측 메뉴(대시보드·도면 등록·유사도 분석·도면 그룹·ECN 관리·변경자재·설정·사용 흐름 안내), 상단 통합검색, 진행 단계 표시(1 등록 → 5 ECN 연결), 도면 등록 3단(업로드·파일 목록 / 미리보기·원문 / 추출정보 편집), 유사도 결과 3단(기준 도면 / 후보 / 비교 패널·그룹 처리·승인 기록), ECN 화면의 「완료 처리 제한」 안내까지 같은 배치입니다. 좁은 화면에서는 1단으로 접힙니다.
- **ECN 화면과 엑셀은 설계변경통보서 양식 그대로입니다.** 1~10절 항목 이름과 순서, 영향도 9개 검토 항목, 수신 부서 6곳, 변경 유형 5종(양식에서 「사양변경」이 추가됨)을 옮겼습니다. 자동 칸(증감, 유형별 건수, 재고처리 미정, 상태, 종결 판정)은 **받은 엑셀의 수식을 그대로 로직으로 옮겼고**, 빈 양식에서 엑셀이 보여 주는 값(「누락: 제품적용일 적용조건 재고처리방안」, 「미검토 9건」, 「대상 없음」)과 같은 값이 나오는지 테스트로 확인했습니다.
- **설계변경통보서 엑셀 출력은 수식 대신 계산된 값**으로 넣습니다. 양식의 A~P 16열 배치와 병합 범위는 따랐고, 변경자재가 10건을 넘으면 행을 늘리고 아래 절을 밀어 내립니다. 글꼴·테두리·색은 넣지 않습니다(내장 SheetJS 무료판이 서식을 쓰지 못함) — 서식까지 같게 하려면 받은 양식 파일에 값을 채우는 방식이 필요합니다(다음 단계).
- **ECN 완료 조건에 「변경자재 담당부서」를 더했습니다.** 양식 8절은 재고처리만 보지만, 원문 6.2 는 「적용일·재고처리·담당부서 미정 시 완료 처리 제한」입니다. 두 기준을 함께 적용했습니다.
- **대시보드·영향도·수평전개·종결 판정·적중 검증을 1단계에 넣었습니다.** v0.1 에서는 확장이었지만 v0.2 에서 수강생이 UI 시안과 양식(6·7·8절, 14 적중 검증표)으로 구체적으로 정의해 주어 MVP 로 옮겼습니다.
- **PDF 는 브라우저 안에서만 읽습니다.** 원문 위험관리(회사정보 외부 유출)를 따른 것입니다. PDF 원본은 저장소에 넣지 않고(용량 한도·보안), 추출한 글자와 정보만 저장합니다. 미리보기는 등록한 창에서만 되고, 나중에는 「원본 다시 연결」로 같은 파일을 고르면 됩니다(해시가 다르면 경고).
- **파일 해시는 FNV-1a(32bit)+크기**입니다. 보안용이 아니라 같은 파일을 가려내는 용도라 가볍게 했고, `file://` 로 열어도 동작합니다.
- **점수는 설명 가능한 규칙으로만 계산합니다.** 항목마다 근거 문장(예: 「공용 6종 / 합계 8종」)을 함께 보여 줍니다.
- **스크립트는 ES module 이 아닌 일반 스크립트**입니다. `index.html` 을 파일로 열면(file://) 브라우저가 module 스크립트를 막기 때문입니다. pdf.js 는 file:// 에서 작업자(worker)를 못 띄우면 같은 창에서 처리하도록 되어 있어, 파일로 열어도 추출·미리보기가 되는 것을 확인했습니다.

## 결정과 이유

- **서버·AI 없이 픽셀 비교** — 사내 도면 유출 우려가 가장 커서, 그림은 canvas 메모리에서만 다루고 localStorage 에도 넣지 않습니다(용량으로도 맞지 않음).
- **PDF 직접 렌더 포함** — 이미 `vendor/pdf.min.js` 로 미리보기를 하고 있어(file:// 에서도 동작 확인된 경로) 같은 로더(`App.loadPdf`)를 썼습니다. 안 열리는 PDF 는 PNG 로 저장해 올리라고 안내합니다.

# 개발일지 — 2026-09-30 · 출력물에 회사 로고

원문 `source/2026-09-30_패들릿_답변4.md`(「색상의 느낌은 매우 만족 … 로고를 출력물에도 포함해 주시면 감사합니다」), 기획서 v0.10 11.7절.

## 한 일

1. **출력물 전수 확인** — 도구가 내보내는 것은 엑셀(xlsx) 단추 15개(설계변경통보서 두 경로 포함) · 도면 비교 그림(PNG) · 백업(JSON)뿐입니다. HTML · Word · 인쇄용 출력은 없습니다(`window.print`·인쇄 CSS 없음, 설계변경통보서도 엑셀).
2. **엑셀 표 전부** (`App.buildXlsx` — `App.downloadXlsx` 를 거치는 모든 단추) — 시트마다 A1 에 로고(56 픽셀, 비율 유지), 표는 `origin: 3` 으로 4행부터. 시트 범위(`!ref`)는 표 시작 줄부터라 다시 불러오면 첫 줄이 머리행. 병합이 있으면 같은 줄 수만큼 내림. `logo: false` 로 뺄 수 있고, `logo: {col,row,height,dx,dy}` 면 표를 밀지 않고 그 자리에 넣음.
3. **설계변경통보서** (`App.exportEcnXlsx`, 예전 경로 `view-ecn` 도) — 양식에서 비어 있던 A1:B4(약 122×80 픽셀) 가운데에 68 픽셀 로고(`App.ECN_LOGO_SLOT`). 행 · 열 · 병합 · 9절 그림 자리는 그대로.
4. **도면 비교 그림 PNG** (`resultImage`) — 머리 띠 왼쪽에 로고(띠 높이 − 8), 글은 로고 오른쪽부터. 통보서 9절 그림 · 「9_도면비교」 큰 그림도 같은 함수라 함께 들어감.
5. **`js/brand-logo.js`** — `img/logo.png` 의 data URI 사본(대체 글 「천일테크윈 로고」, `bytes()` · `widthFor(h)` · 미리 불러 둔 `img`). `scripts/make-logo-js.js` 로 다시 만듦.
6. **`js/xlsx-image.js`** — 같은 그림 배열을 여러 번 넣으면 `xl/media` 파일 하나를 함께 씀(시트 7개 = 로고 파일 1개), 칸 안 여백(`dx` · `dy`), 설명(`descr`).

## 결정과 이유

- **ExcelJS 를 들이지 않음** — SheetJS 무료판은 그림을 못 쓰지만, 9절 그림 때 만든 zip 덧붙이기(`xlsx-image.js`)가 이미 있고 검증돼 있어 그대로 씁니다. 새 라이브러리(약 1MB)를 받을 까닭이 없고 폐쇄망 · 파일 열기도 그대로입니다.
- **로고를 파일이 아닌 사본(data URI)으로** — 파일(file://)로 연 도구에서는 `img/logo.png` 를 fetch 로 못 읽고, 그 파일을 캔버스에 그리면 캔버스가 오염돼 PNG 저장이 막힙니다. data URI 는 둘 다 괜찮습니다.
- **엑셀 표는 밀고, 통보서는 밀지 않음** — 표에는 로고 둘 자리가 없어 3줄 밀었고, 통보서는 받은 양식의 행 번호가 기준이라 비어 있던 A1:B4 칸을 씁니다.
- **다시 불러오기를 깨지 않게 `!ref` 를 표 시작 줄부터** — 도면 대장 가져오기는 첫 줄을 머리행으로 읽습니다(`sheet_to_json` 기본). 범위를 A1 부터 두면 빈 줄이 머리행이 되어 `__EMPTY` 열이 생깁니다.
