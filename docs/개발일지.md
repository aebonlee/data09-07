## 결정과 이유

- **화면은 수강생 UI 시안을 따랐습니다.** 좌측 메뉴(대시보드·도면 등록·유사도 분석·도면 그룹·ECN 관리·변경자재·설정·사용 흐름 안내), 상단 통합검색, 진행 단계 표시(1 등록 → 5 ECN 연결), 도면 등록 3단(업로드·파일 목록 / 미리보기·원문 / 추출정보 편집), 유사도 결과 3단(기준 도면 / 후보 / 비교 패널·그룹 처리·승인 기록), ECN 화면의 「완료 처리 제한」 안내까지 같은 배치입니다. 좁은 화면에서는 1단으로 접힙니다.
- **ECN 화면과 엑셀은 설계변경통보서 양식 그대로입니다.** 1~10절 항목 이름과 순서, 영향도 9개 검토 항목, 수신 부서 6곳, 변경 유형 5종(양식에서 「사양변경」이 추가됨)을 옮겼습니다. 자동 칸(증감, 유형별 건수, 재고처리 미정, 상태, 종결 판정)은 **받은 엑셀의 수식을 그대로 로직으로 옮겼고**, 빈 양식에서 엑셀이 보여 주는 값(「누락: 제품적용일 적용조건 재고처리방안」, 「미검토 9건」, 「대상 없음」)과 같은 값이 나오는지 테스트로 확인했습니다.
- **설계변경통보서 엑셀 출력은 수식 대신 계산된 값**으로 넣습니다. 양식의 A~P 16열 배치와 병합 범위는 따랐고, 변경자재가 10건을 넘으면 행을 늘리고 아래 절을 밀어 내립니다. 글꼴·테두리·색은 넣지 않습니다(내장 SheetJS 무료판이 서식을 쓰지 못함) — 서식까지 같게 하려면 받은 양식 파일에 값을 채우는 방식이 필요합니다(다음 단계).
- **ECN 완료 조건에 「변경자재 담당부서」를 더했습니다.** 양식 8절은 재고처리만 보지만, 원문 6.2 는 「적용일·재고처리·담당부서 미정 시 완료 처리 제한」입니다. 두 기준을 함께 적용했습니다.
- **대시보드·영향도·수평전개·종결 판정·적중 검증을 1단계에 넣었습니다.** v0.1 에서는 확장이었지만 v0.2 에서 수강생이 UI 시안과 양식(6·7·8절, 14 적중 검증표)으로 구체적으로 정의해 주어 MVP 로 옮겼습니다.
- **PDF 는 브라우저 안에서만 읽습니다.** 원문 위험관리(회사정보 외부 유출)를 따른 것입니다. PDF 원본은 저장소에 넣지 않고(용량 한도·보안), 추출한 글자와 정보만 저장합니다. 미리보기는 등록한 창에서만 되고, 나중에는 「원본 다시 연결」로 같은 파일을 고르면 됩니다(해시가 다르면 경고).
- **파일 해시는 FNV-1a(32bit)+크기**입니다. 보안용이 아니라 같은 파일을 가려내는 용도라 가볍게 했고, `file://` 로 열어도 동작합니다.
- **점수는 설명 가능한 규칙으로만 계산합니다.** 항목마다 근거 문장(예: 「공용 6종 / 합계 8종」)을 함께 보여 줍니다.
- **스크립트는 ES module 이 아닌 일반 스크립트**입니다. `index.html` 을 파일로 열면(file://) 브라우저가 module 스크립트를 막기 때문입니다. pdf.js 는 file:// 에서 작업자(worker)를 못 띄우면 같은 창에서 처리하도록 되어 있어, 파일로 열어도 추출·미리보기가 되는 것을 확인했습니다.

## 가정 (확인 필요)

- **항목별 점수 계산 방식** — 원문에는 가중치와 예시만 있어 다음처럼 정했습니다. 샘플 도면으로 조정할 부분입니다.
  - 제품군 25: 고객사 같음 절반 + 기종 같음 또는 파생(한쪽이 다른 쪽으로 시작, 예: X1 / X1-L) 절반
  - 사용처 20: 사용처 같음 60퍼센트 + 품명 낱말 겹침 40퍼센트
  - 부품 30: 주요 커넥터·전선·보호재 목록의 공용률(겹침 ÷ 합집합). BOM 연결 전까지는 도면에서 뽑은 목록을 씁니다
  - 문자 15: 구조 키워드 겹침
  - 형상 10: 회로 수·분기 수가 가까운 정도의 평균
- **기준점수 70** — UI 시안 표기를 초기값으로 썼습니다(10장 6번). 판정은 「기준점수 이상인 후보 중 그룹이 있는 가장 높은 후보의 그룹 → 기존 그룹 후보」, 그런 후보가 없으면 신규 그룹 후보입니다.
- **적중 검증** — 정답이 「신규 그룹」인 도면은 1순위 점수가 기준점수 미만일 때 적중으로 셉니다.
- **제목란 추출 규칙** — `PART NO.`/`품번`/`도번`, `REV`/`개정`, `TITLE`/`품명`, `MODEL`/`기종`, `CUST.`/`고객사`, `APPLY`/`사용처` 라벨 뒤 값을 읽고, 파일명 `품번_REV.pdf` 를 보조로 씁니다. 부품번호 모양(`CN-0221` 같은 영문 2~4자-숫자)과 키워드 사전은 설정에서 고칠 수 있는 임시 값입니다.
- **양식 3·4·5·6·14 의 열 구성** — 원 기획서 PDF 에서 번호에 해당하는 양식 정의를 찾지 못해, 기획서 3장 데이터 항목과 설계변경통보서 열로 정했습니다.
- **선택 목록 값** — 받은 엑셀의 드롭다운 목록 참조가 끊겨(#REF!) 있어, 변경 유형·해당 여부(해당/비해당)·적용 여부(검토 중/적용/미적용)만 목록으로 두고 설변 종류·재고 처리·담당 부서 등은 글로 입력합니다.
- 예시 데이터의 품번·고객사·기종 표기는 UI 시안의 익명화 샘플 모양을 따랐고, 받은 엑셀 작성 예시의 실명·고객사명은 쓰지 않았습니다.
